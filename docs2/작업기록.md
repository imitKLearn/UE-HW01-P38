### 풀어야 했던 것

`WBP_Title`의 `ServerIP` 입력칸 하나가 두 가지 주소를 겸하고 있었다.

- **웹서버 주소** — 로그인/회원가입 HTTP 요청의 대상
- **게임서버 주소** — `ConnectServer`의 `OpenLevel` 대상

그래서 접속하려는 사람이 게임서버 IP를 말로 전해 듣고 손으로 적어 넣어야 했다. 이번 작업이 그 겸직을 풀고 IP 전달을 웹서버 경유로 자동화한다.

## 2. 확정된 설계 결정

| 결정 | 근거 |
|---|---|
| 게임서버 IP는 **UE가 `ISocketSubsystem`으로 직접 탐지**해 전송 | 웹서버가 `request.client.host`로 추정하면, 웹서버와 게임서버가 같은 PC일 때 `127.0.0.1`이 등록되어 다른 PC 클라이언트가 접속하지 못한다 |
| 등록 IP는 **파이썬 모듈 변수**에 보관 | DDL 실행이 필요 없다. 웹서버를 재시작하면 초기화되므로 죽은 서버 IP가 남지 않는다 |
| **최신 1개만** 유지하고 `/login` 응답에 동봉 | 새 조회 엔드포인트도, 서버 목록 UI도 필요 없다 |
| `WBP_Title`에 **`GameServerIP` 입력칸 신설** | 아래 3절 참고. 칸 하나를 겸용하면 요구사항 1이 조용히 깨진다 |
| 등록 **응답을 기다린 뒤** 레벨을 연다 | 실패해도 그냥 서버가 뜨면 등록됐는지 확인할 방법이 없다. 실패 시 InfoText에 표시하고 이동하지 않는다 |
| 포트는 등록하지 않는다 | 게임서버는 UE 기본 7777이고 `OpenLevel(IP)`도 기본 포트를 쓴다 |
| `/register_server`도 **같은 `AuthResponse` 모델**을 쓴다 | UE의 기존 `{result, message}` 파싱 경로를 그대로 재사용하기 위해서다 |

### 응답 계약 (기존 형식 그대로 확장)

```json
{ "result": true, "message": "", "idx": 1, "nickname": "junios", "level": 1, "server_ip": "192.168.0.5" }
```

`server_ip`는 로그인 성공 시에만 의미가 있고, 등록된 서버가 없으면 `""`다.

| 상황 | HTTP | result | server_ip |
|---|---|---|---|
| 서버 등록 성공 | 200 | `true` | 등록한 IP |
| 등록 요청의 `ip`가 빈 값 | 422 | — | Pydantic `min_length=1`이 거부 |
| 로그인 성공, 등록 서버 있음 | 200 | `true` | 그 서버 IP |
| 로그인 성공, 등록 서버 없음 | 200 | `true` | `""` |
| 로그인 실패 | 200 | `false` | `""` |

## 3. 왜 입력칸을 하나 더 만들었나

처음 설계는 받은 게임서버 IP를 기존 `ServerIP` 칸에 자동으로 채우는 것이었다. 코드 흐름을 따라가 보니 깨진다.

`ServerIP` 칸은 `Login()`, `SignUp()`, 그리고 새로 만든 `StartServer()`가 **웹서버 주소로 읽는** 값이다. 여기에 게임서버 IP를 덮어쓰면:

1. 두 번째 사람이 로그인한다 → 칸에 남의 게임서버 IP가 채워진다
2. 그 사람이 StartServer를 누른다 → 등록 요청이 웹서버가 아니라 **남의 게임서버로 간다**
3. 요구사항 1이 깨진다

첫 로그인 때는 등록된 서버가 없어 칸이 바뀌지 않으므로, 혼자 테스트할 때는 걸리지 않고 여러 명이 쓸 때만 터진다. 칸 하나가 두 주소를 겸할 수 없다고 판단해 `GameServerIP` 칸을 신설했다.
